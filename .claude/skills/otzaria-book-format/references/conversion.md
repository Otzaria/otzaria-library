# המרת טקסט למבנה אוצריא — הצינור

מקור הסמכות: `lib/utils/text/otzaria_markup.dart` ב-repo התוכנה — מוגדר שם במפורש
כ**"חוזה ה-markup של טקסט אוצריא (§24) — מקור יחיד"**, וכל הממירים המובנים (HTML,
DOCX, EPUB, ODT, RTF, Markdown, Word ישן) מייצרים לפיו את **אותן תגיות בדיוק**.
המפות בפועל: `lib/utils/file/html_to_otzaria.dart`.

## 0. לפני שממירים ידנית — יש ממיר מובנה?

לאוצריא ממירים לכל אלה: `.html/.htm`, `.docx`, `.doc`, `.epub`, `.odt`, `.rtf`, `.md`.
אם המקור באחד מהפורמטים האלה — התוכנה כבר יודעת להמיר, והפלט תואם לחוזה. המרה
ידנית נחוצה כשהמקור הוא אתר, API, JSON, OCR, טקסט גולמי, או כשצריך שליטה על
הכותרות והחלוקה לשורות (המקרה הרגיל בספרייה).

## 1. חוזה הפלט

**הפלט נבנה מאפס. לעולם אין מעתיקים markup מהמקור** — כל תגית נכתבת מרשימת ההיתר,
וכל ערך ב-`style`/`href`/`src` עובר אימות. זה ניסוח החוזה בקוד, וזו גם הדרך היחידה
לא לגרור לספר תגיות זבל.

### נמחקים עם התוכן (אין בהם טקסט קריא)

`applet` `area` `audio` `base` `button` `canvas` `datalist` `dialog` `embed` `frame`
`frameset` `head` `iframe` `input` `link` `map` `meta` `meter` `noframes` `noscript`
`object` `optgroup` `option` `param` `progress` `script` `select` `source` `style`
`svg` `template` `textarea` `title` `track` `video`

### בלוק = שובר שורת ספר

`address` `article` `aside` `blockquote` `caption` `center` `details` `div` `dd` `dl`
`dt` `fieldset` `figcaption` `figure` `footer` `form` `h1`–`h6` `header` `hgroup`
`hr` `legend` `li` `main` `menu` `nav` `ol` `p` `pre` `section` `summary` `table`
`tbody` `td` `tfoot` `th` `thead` `tr` `ul`

`<img>` **אינו** בלוק — הוא inline בטבעו (אחרת היה נעלם מתוך פריט רשימה או תא טבלה).

### inline שנשמר — עם מיפוי לתגית שהמנוע מכיר

| מקור | נכתב כ | |
|---|---|---|
| `b`, `strong` | `b` | |
| `i`, `em`, `cite`, `dfn`, `var` | `i` | `<i>` נתמך גם במצב קריאה רציפה |
| `u`, `ins` | `u` | |
| `s`, `del`, `strike` | `s` | |
| `sub`, `sup` | כשם המקור | |
| `small`, `big` | כשם המקור | |
| `code`, `kbd`, `samp`, `tt` | `code` | |
| `abbr`, `acronym` | `abbr` | קו מנוקד |
| `ruby`, `rt`, `rp` | כשם המקור | בלי שימור — «אנפיןפנים», כלומר אובדן תוכן |

**כל השאר שקוף (unwrap):** `span`, `label`, `q`… — הטקסט נשמר, העיצוב נקרא בנפרד
מ-`style`. **תגית לא מוכרת אינה מוחקת תוכן.** הכלל המנחה בקוד:
*אובדן עיצוב מותר; אובדן תוכן — לא.*

### קישורים ותמונות

- `href`: רשימת היתר `http`, `https`, `mailto` + עוגן פנימי (`#…`) + נתיב יחסי.
  `javascript:`, `data:`, `file:`, `otzaria://` — נפסלות, והקישור מוצג כטקסט בלבד.
  `book://` מותרת **רק** בנתיב שמתעד אותה (HTML/כתיבה ידנית), לא בייבוא כללי.
- `src` של תמונה: data-URI מאומת, או קובץ בתוך תיקיית הספר. כתובת רשת — מדולגת.
- הפונקציות הקנוניות: `otzariaImage(...)` (מוסיפה `style="max-width: 100%;"`),
  `otzariaFootnote(marker, body)`, `otzariaTableOpen()` + `otzariaTableCellStyle`.

### שורה

`otzariaInlineText()` מחליף כל `\r`/`\n` **בתוך** יחידת תוכן ברווח. ירידת שורה בפלט
= שורה חדשה בספר, ולכן פסקה שנשברה = אינדקסים זזים מול תוכן העניינים, ההערות
והסימניות. רוצים שבירה ויזואלית בתוך שורה — `<br>`.

## 2. הצינור

### שלב 1 — חילוץ ונרמול

- לקרוא את המקור, לזהות קידוד, ולהמיר ל-UTF-8.
- **לחלץ הערות שוליים לפני פיצול השורות** — הן מכילות `<br>` פנימיים ופיצול מוקדם
  שובר אותן.
- לכווץ רצפי רווח לבן; להמיר `&nbsp;` לפי הצורך.

### שלב 2 — בלוק לשורה

כל אלמנט בלוק פותח שורה חדשה. רצף inline חשוף בין בלוקים (טקסט ישיר בתוך `div`)
נאסף לשורת פסקה משלו כדי שלא ייבלע.

**מבנה מרובה-חלקים נכתב כשורה אחת:** רשימה שלמה (`<ol>…</ol>`), טבלה שלמה
(`<table>…</table>`), `<details>`, `<ruby>` — הכול ברצף אחד.

### שלב 3 — כותרות והיררכיה

- שורה 1: `<h1>שם הספר</h1>`. שורה 2: שם המחבר, או ריקה.
- כותרות הן שכבת הניווט; מותר ורצוי לנרמל את **נוסח הכותרת** (פתיחת קיצורים,
  הוספת "מסכת", צורה קנונית של שם פרק) — זה לא גוף הספר.
- **גוף הספר הוא טקסט מקור.** אין להוסיף מילים, לפתוח קיצורים, לתקן לשון או להשלים
  חוסרים. מותרות רק פעולות מבניות: קיטוע/איחוד שורות, סימון דיבור-המתחיל ב-`<b>`,
  והעברת סמן מבני שהוא באמת כותרת אל שורת כותרת.
- היררכיה רציפה, בלי דילוג רמות; כותרת = שורה שלמה; אין h7+.

### שלב 4 — הערות שוליים

שני מנגנונים נתמכים; בחרו אחד ושמרו עליו לאורך כל הספר:

| מנגנון | מתי | איך |
|---|---|---|
| inline | ספר חדש, בלי קבצים נלווים | `<sup class="footnote-marker">N</sup><i class="footnote">גוף</i>` צמודים |
| קובץ נפרד | תאימות לפייפליין קיים (ספריא) | `הערות על <ספר>.txt` + `links/<ספר>_links.json`; הסמן בגוף: `<sup style="color: gray;">N</sup>` |

הסקריפט `otzaria/utils.py::footnotes()` בספרייה הוא ההמרה מהראשון לשני.

### שלב 5 — ניקוי סופי לכל שורה

- להסיר תגיות מחוקות עם תוכנן, לפרוק (unwrap) תגיות לא מוכרות.
- **לוודא שכל שורה מאוזנת בפני עצמה** — פרסור מחדש של השורה סוגר תגיות פתוחות.
- לוודא **תיבה אחת לכל היותר** בשורה (`<sup>`/`<sub>` לא-מספרי, `inline-block`, `img`).
- לוודא שאין `id`, `<style>`, `<script>`, `rem`, `text-emphasis`,
  `text-align` על `span`.

### שלב 6 — שם ומיקום

- שם הקובץ = שם הספר אחרי `sanitize_filename` (ראו `metadata.md`): בלי ניקוד/טעמים
  ובלי `\ / : * " ״ ? < > |`. ה-`<h1>` שומר את הצורה המלאה עם גרשיים.
- המיקום בתיקיות **הוא** הקטגוריה. לבחור את הענף הקיים המתאים, לא ליצור ענף חדש
  בלי צורך.
- לבדוק שאין ספר קיים באותו שם מנוקה (התנגשות שם).

### שלב 7 — מטא-דאטה

רשומה ב-`all_metadata.json` (ובמקורות שיש להם `otzaria_metadata.json` משלהם), ולפי
הצורך שורות ב-`ForDB/generations.csv` וכו׳. הפירוט והשדות: `metadata.md`.
`scripts/make_metadata.py` מייצר רשומה מלאה, בודק התנגשות שם, וממזג לקובץ.

### שלב 8 — ולידציה

```bash
python -X utf8 scripts/validate_book.py "…/ספר.txt"
python -X utf8 scripts/inspect_book.py "…/ספר.txt" --toc --stats
python -X utf8 scripts/validate_sidecars.py --links "…/ספר_links.json" --book "…/ספר.txt"
```

## 3. הכלי

```bash
# HTML/Markdown/טקסט גולמי → מבנה אוצריא, לפי החוזה
python -X utf8 scripts/to_otzaria.py --in source.html --out "שם הספר.txt" \
       --title "שם הספר" --author "שם המחבר"

python -X utf8 scripts/to_otzaria.py --in source.md --format md --out "ספר.txt" --title "ספר"

# הערות inline → קובץ הערות נפרד + links (המנגנון של ספריא)
python -X utf8 scripts/to_otzaria.py --in source.html --out "ספר.txt" --title "ספר" \
       --split-footnotes --links-dir ../links
```

הסקריפט מיישם את החוזה: מחיקת התגיות המחוקות, בלוק→שורה, מיפוי ה-inline, unwrap
ללא-מוכר, כיווץ רווח לבן, אימות `href`/`src`, רשימות וטבלאות בשורה אחת, והערות
שוליים בשני המנגנונים. הפלט תמיד עובר את `validate_book.py`.

## 4. מלכודות שחוזרות בכל המרה

| מלכודת | תיקון |
|---|---|
| פסקה שנשברה לשתי שורות | `\n` בתוך יחידת תוכן → רווח; שבירה ויזואלית ב-`<br>` |
| רשימה/טבלה שנפרסה על כמה שורות | לכתוב את כל המבנה בשורה אחת |
| תג פתוח בסוף שורה | לפרסר מחדש כל שורה ולסגור |
| הערות שוליים שפוצלו לפני החילוץ | לחלץ הערות **לפני** פיצול השורות |
| כותרת עם טקסט אחריה | לפצל לשתי שורות |
| שני `<sup>` לא-מספריים באותה שורה | לפצל לשתי שורות (מלכודת ההיפוך) |
| `&lt;`/`&gt;` שנשארו כטקסט או פוענחו פעמיים | להריץ unescape פעם אחת, במקום הנכון בצינור |
| שם קובץ עם גרשיים | `sanitize_filename`; הגרשיים נשארים ב-`<h1>` |
| ניקוד/טעמים בשם הקובץ | מוסרים ע"י אותה פונקציה |
