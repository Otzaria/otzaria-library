# קובץ הספר — הפורמט

## מקורות (כל טענה כאן נבדקה מול אחד מאלה)

| קיצור | מה זה |
|---|---|
| **המדריך** | `MoreBooks/ספרים/אוצריא/אודות התוכנה/עריכת ספר באוצריא.txt` — המדריך הרשמי, בעצמו ספר באוצריא. פתחו אותו גם בעורך טקסט כדי לראות את התגים. |
| **הקוד** | repo התוכנה: `lib/utils/file/toc_parser.dart`, `lib/text_book/utils/inline_notes_utils.dart`, `lib/utils/text/css_whitelist.dart`, `lib/migration/generator/generator.dart`, `lib/text_book/view/widgets/continuous_reading_paragraph.dart`, `pubspec.yaml`. |
| **הסקריפטים** | repo הספרייה: `sefariaToOtzaria/סקריפטים/otzaria/{utils,get_from_export}.py`, `.github/scripts/validate_fordb_book_names.py`, `docs/קישורים-וכותרות.md`. |

מה שמסומן «לפי המדריך» — לא אומת בקוד; מה שמסומן «בקוד» — נקרא בקוד עצמו.

## 0. הבסיס

- קידוד UTF-8. `.txt` (גם `.docx`/`.pdf` נתמכים כסוגי ספר, אבל רק `.txt` מקבל מבנה מלא).
- **כל שורה פיזית = יחידת תוכן.** ירידת שורה = שורה חדשה. אין פסקאות רב-שורתיות, ואין
  תג שנמשך בין שורות. ירידת שורה בתוך יחידת תוכן — `<br>` (כך עושים הסקריפטים).
- שורה 1: `<h1>שם הספר</h1>` לבדה.
- שורה 2: **שם המחבר, או ריקה.** (בסקריפט של ספריא: שורת המחברים נכתבת רק אם יש
  מחברים בסכימה.)
- שורות ריקות מותרות ונספרות במספור השורות, אך אינן מקבלות קישור.

### שם הספר מול `<h1>`

**זהות הספר נגזרת משם הקובץ, לא מה-`<h1>`** (בקוד: `generator.dart` —
`path.basenameWithoutExtension(bookPath)`). ה-`<h1>` הוא שורת התצוגה הראשונה ושורש
תוכן העניינים.

לכן הם **יכולים ולעיתים חייבים להיות שונים**: `sanitize_filename` מסירה משם הקובץ
תווים שאסורים בשם קובץ ב-Windows — `\ / : * " ״ ? < > |` — וגם ניקוד וטעמים, גרש
וגרשיים בודדים, ו-`_`→רווח. ה-`<h1>` שומר את השם המלא כפי שראוי להציגו
(`<h1>שו"ת מהרש"ם חלק ג</h1>` בקובץ `שות מהרשם חלק ג.txt`).

מסקנה מעשית: להפניה לספר (`book://`, `path_2`) משתמשים **בשם הספר כפי שהוא במאגר**,
לא בטקסט ה-`<h1>` ולא בהכרח בשם הקובץ הגולמי. אמתו: `scripts/query_db.py book "<שם>"`.

### שלושת כללי היסוד «לפי המדריך»

1. **כל שורה עומדת בפני עצמה.** תג שנפתח בשורה לא ממשיך לשורה הבאה. עיצוב על חמש
   שורות — נכתב חמש פעמים.
2. **תג שלא נסגר חל עד סוף השורה.** לא שגיאה, אבל במצב קריאה רציף (שבו שורות מתמזגות)
   העיצוב ידלוף. סגרו הכול.
3. **מבנה מרובה-חלקים = שורה אחת.** `<ol>`, `<ul>`, `<table>`, `<details>`, `<ruby>` —
   כל המבנה ברצף אחד בלי ירידת שורה.

תג שאינו מוכר — מתעלמים ממנו, הטקסט שבתוכו מוצג רגיל.

## 1. כותרות ותוכן העניינים

```
<h1>שם הספר</h1>       ← שורה 1
<h2>חלק / מסכת</h2>
<h3>פרק / סימן</h3>
<h4>…</h4>  <h5>…</h5>  <h6>…</h6>
```

**מה שהקוד עושה בפועל** (`lib/utils/file/toc_parser.dart`):

- שורה נחשבת כותרת אם אחרי `trimLeft` היא **מתחילה** ב-`<h1`…`<h6`. כותרת באמצע שורה
  — לא מזוהה כלל.
- טקסט הכותרת = כל השורה אחרי הסרת התגים. כלומר טקסט שנשאר אחרי `</h2>` באותה שורה
  **ייבלע לתוך שם הכותרת** בתוכן העניינים. לכן הכלל שבמדריך — הכותרת לבדה בשורה.
- `<h2 data-toc="none">` — מזוהה ומוחרג מתוכן העניינים (`kTocExcludeAttr`).
- כותרות Markdown (`#` עד `######` + רווח) **כן** מזוהות בקוד — אבל הסולמיות יוצגו
  לקורא כטקסט. אין להשתמש בהן «לפי המדריך».
- היררכיה: רמה ≤1 = שורש; אחרת ההורה הוא הכותרת האחרונה ברמה `level-1`. **דילוג רמה
  (h2→h4) משאיר את הכותרת בלי הורה** ושובר את העץ.
- אין `<h7>` ומעלה.
- גדלים יחסיים לגופן שהמשתמש בחר «לפי המדריך»: h1 ×2, h2 ×1.5, h3 ×1.17, h4 ×1,
  h5 ×0.83, h6 ×0.67 — h5/h6 קטנות מטקסט רגיל. כותרות מודגשות אוטומטית: בלי `<b>`
  ובלי `<big>`.
- הכותרת היא היעד של קישור פנימי (`#טקסט הכותרת`) ושל `book://ספר#כותרת`, ולכן ניסוחה
  הוא ממשק ולא רק עיצוב.
- **קישור אינו יכול להצביע על שורת כותרת** — הגנרטור מדלג על קישור שאחד מקצותיו
  `<h…>` (`docs/קישורים-וכותרות.md`, "שער כותרות").

## 2. הערות שוליים

### א. המנגנון הפנימי (inline)

```html
מילה<sup class="footnote-marker">1</sup><i class="footnote">גוף ההערה</i> המשך
```

**בקוד** (`lib/text_book/utils/inline_notes_utils.dart` — התיעוד שם מציין ≈322 ספרים
ב-DB שמשתמשים בזה):

- הגוף מזוהה כ-`<i …class="…footnote…">…</i>`; הסמן — `<sup …footnote-marker…>…</sup>`
  שחייב להסתיים **מיד לפני** הגוף (בין השניים מותר רק רווח לבן; המדריך דורש בלי רווח
  כלל — כתבו צמוד).
- הגוף **מוסר** מגוף השורה ומוצג כמפרש וירטואלי בצד ובריחוף עכבר; הוא אינו מזהם
  את החיפוש בגוף הספר.
- סמן שתוכנו **ספרות בלבד** מומר לספרות-עיליות יוניקוד ועטוף LRI/PDI, ומקבל
  `class="book-note-marker-sup"`; סמן אחר נשאר סמן טקסטואלי (`book-note-marker`).
  הסיבה בקוד: HtmlWidget לא תומך בהגבהת CSS, ו-`<sup>` אמיתי מתהפך ב-RTL.
- לכן: מספרי הערות אינם ניתנים להגדלה/צביעה — זה מכוון.

### ב. המנגנון בקובץ נפרד (הרווח בספרייה)

שלושה קבצים: `<ספר>.txt` + `הערות על <ספר>.txt` + `links/<ספר>_links.json` עם
`"heRef_2": "הערות"` ו-`"Conection Type": "commentary"`; בקובץ ההערות שורה N היא
ההערה מספר N, ואין בו `<h1>`.

**זה מה שהפייפליין של ספריא מייצר בפועל**: `otzaria/utils.py::footnotes()` מוצא כל
`<sup class="footnote-marker">`, מסיר את ה-class ומחליף ב-`style="color: gray;"`,
ומחלץ את ה-`<i class="footnote">` הצמוד לרשימת הערות נפרדת.

שני המנגנונים נתמכים. לספר חדש שנכתב ידנית — הפנימי פשוט יותר (בלי קבצים נלווים);
לספר שמגיע מפייפליין קיים — אל תשנו את המנגנון בלי סיבה.

## 3. קישורים בתוך הטקסט «לפי המדריך»

| מטרה | כתיבה |
|---|---|
| אתר / דואר | `<a href="https://…">` · `<a href="mailto:…">` |
| ספר אחר | `<a href="book://שולחן ערוך, אורח חיים">` |
| ספר + כותרת | `<a href="book://שולחן ערוך, אורח חיים#סימן ט">` |
| כמה רמות | `<a href="book://בית יוסף#אורח חיים#סימן א#סעיף קטן יג">` |
| בתוך אותו ספר | `<a href="#טקסט הכותרת">` |
| מראית קישור בלי קישור | `<a href><sup>1</sup></a>` |

- `book://` — שם הספר בדיוק כפי שהוא במאגר. ירידה בעץ: כל רמה נחפשת רק בתוך זו
  שמעליה; מותר לדלג רמות ביניים; רמה שלא נמצאה → נחיתה על העמוקה שנמצאה + הודעה.
- קישור פנימי מתאים לפי **טקסט הכותרת**, לא לפי `id`. `id` אינו בשימוש.
- `file://` תלוי בנתיב אצל הקורא — לא לספרים מופצים.
- `otzaria://` שמור לתוכנה (ריחוף הערות, עוגני-מילה).

## 4. תגים

**מנוע הרינדור הוא `flutter_widget_from_html ^0.17.3`** (`pubspec.yaml`,
`lib/widgets/smart_text/smart_text_widget.dart`) — ה-HTML של השורה מועבר אליו כמות
שהוא. כלומר: מה שנתמך = מה שהחבילה תומכת, ולא רשימה שאוצריא מגדירה. הרשימה שלהלן היא
**מה שהמדריך הרשמי מתעד כנבדק**, וזה מה שכדאי להסתמך עליו:

| תחום | תגים |
|---|---|
| כותרות | `h1`–`h6` (+`data-toc="none"`) |
| הדגשה/נטייה | `b`, `strong`, `i`, `em`, `var`, `cite`, `dfn` |
| גודל | `big`, `small` (ניתן לקינון) |
| קווים | `u`, `ins`, `s`, `del`, `strike`, `acronym`, `abbr` (קו מנוקד) |
| סימון | `mark` |
| עילי/תחתי | `sup`, `sub` |
| הערות | `sup class="footnote-marker"` + `i class="footnote"` |
| קישור | `a href` |
| מתקפל | `details` + `summary` (שורה אחת; `open`) |
| רשימות | `ol`, `ul`, `li` (`start`, `reversed`, `type`) — שורה אחת |
| טבלאות | `table`, `tr`, `td`, `th`, `caption` (`border`, `cellpadding`, `colspan`, `rowspan`) — שורה אחת |
| בלוקים | `div`, `p`, `blockquote`, `center`, `hr`, `pre` |
| שבירה/תמונה | `br`, `img` (מומלץ `data:` base64; `width`/`height`/`alt`/`title`) |
| ניקוד עליון | `ruby` + `rt` (שורה אחת; כמה בשורה מותרים) |

ישויות: `&lt;` `&gt;` `&nbsp;` `&hellip;` `&mdash;` `&laquo;` `&raquo;` `&#NNNN;`.

**סייג:** תג שאינו ברשימה אינו בהכרח "לא עובד" — ייתכן ש-fwfh מרנדר אותו. אבל הוא
לא נבדק, ואינו מובטח לשרוד המרות (ייבוא/ייצוא Word/מצב קריאה רציף). אם צריך תג שלא
ברשימה — בדקו אותו בפועל באפליקציה לפני שמפיצים ספר שתלוי בו.

## 5. CSS

| מקור | מה הוא אומר |
|---|---|
| ספר ספרייה | ה-`style` עובר כמות שהוא ל-HtmlWidget. |
| ייבוא (HTML/Markdown/EPUB/DOCX → אוצריא) | עובר דרך `lib/utils/text/css_whitelist.dart` — **רשימת היתר כפולה**: גם שם התכונה וגם הערך חייבים לעבור מאמת ייעודי, אחרת ההצהרה נמחקת. |

הרשימה הזו היא התיעוד הטוב ביותר למה שהמנוע באמת מכיר. התכונות שבה (בקוד):

`color` · `background-color` · `background` · `font-weight` · `font-style` ·
`font-size` · `font-family` · `line-height` · `text-align` · `vertical-align` ·
`white-space` · `direction` · `display` · `text-decoration` (+`-line`, `-style`,
`-color`, `-thickness`) · `text-shadow` · `list-style-type` · `border`
(+`-top/-right/-bottom/-left`, `-style`, `-width`, `-color`) · `padding` (+4 צדדים) ·
`margin` (+4 צדדים) · `width` · `height`.

ערכים (בקוד + המדריך):

- **יחידות אורך:** `px`, `pt`, `em`, `%` בלבד. **`rem` נדחית** (`_length` ב-`css_whitelist`).
- `font-weight`: `bold`/`normal`/100–900. `bolder`/`lighter` — לא.
- `font-style`: `italic`/`normal`. `oblique` — לא.
- `font-family`: שם מרובה-מילים **חייב מרכאות בודדות**; מומלץ רשימת גיבוי.
- צבעים: שם צבע, `#RGB`, `#RRGGBB`, `#RRGGBBAA`, `rgb()`, `rgba()`, `hsl()`.
- `text-decoration-thickness`: **אחוזים בלבד**.
- `text-align`: **רק על תג בלוק** — `_blockOnlyProperties` בקוד מוציא אותה מ-`span`.
- `direction: ltr`: עובד רק יחד עם `display:inline-block`.
- `text-shadow`: 2–4 ערכים לכל צל (5+ → כל התכונה נזרקת).
- `display`: `inline-block`, `none` (טקסט מוסתר **נשאר בחיפוש**).

ברירת המחדל: שורה מיושרת לשני הצדדים (justify). פסקה קצרה נראית "מיושרת לימין" כי
אין מה למתוח — לא תקלה.

## 6. מה אינו עובד — ולמה

**הסיבה השורשית:** fwfh הוא ממיר HTML→Flutter Widgets, לא מנוע דפדפן. אין JS, אין
CSS גלובלי, אין hover-state של דפדפן. בנוסף, בנתיב הייבוא רשימת ההיתר היא גם הגנה:
ערך שמכיל גרש יכול לפרוץ מ-`style="…"` ולהזריק תגיות לגוף הספר ולאינדקס (מתועד בקוד).

| לא עובד | הערה |
|---|---|
| `<style>`, CSS חיצוני, class-ים גלובליים | אין עיצוב מרוכז. כל עיצוב inline ובכל שורה מחדש. |
| `<script>`, `onmouseover`, כל JS | חסום. |
| `:hover`, tooltip מ-`title=""` | אין דרך החבילה. |
| `id` כעוגן | קישור פנימי לפי טקסט כותרת. |
| `position`, `transform`, `float`, `opacity`, `border-radius`, `animation`, media-query | לא ברשימת ההיתר ולא נתמך בקורא. |
| `text-emphasis` | הופך כל אות לתיבה → המילה מוצגת הפוכה. |
| `rem`, `oblique`, `bolder`/`lighter`, `rebeccapurple` | כתבו `em`/`%`, `italic`, `bold`/מספר, HEX. |
| `text-decoration-thickness` ב-px | אחוזים בלבד. |
| `text-align` על `span` | תג בלוק בלבד. |
| שם גופן מרובה-מילים בלי מרכאות | תיקרא רק המילה הראשונה. |

### מלכודת ההיפוך RTL

עיצובים מסוימים הופכים ל"תיבה" בתוך השורה, ובטקסט RTL **שתי תיבות באותה שורה מסודרות
בסדר הפוך** — הטקסט ביניהן נראה הפוך והרווחים זזים.

תיבות: `<sup>` **עם אטריביוט או עם תג מקונן** · `display:inline-block` (כולל תיבה
ממוסגרת ו-`direction:ltr`) · `<img>` בתוך שורת טקסט.

**כלל: תיבה אחת לכל שורה.** צריך שתיים — פצלו לשתי שורות.

מה שאינו תיבה, לפי `TextRendererService._fixFootnoteMarkers` ו-`_fixSubscripts`
(«בקוד», `lib/widgets/smart_text/text_renderer_service.dart`; ההסבר המלא בהערת
ה-library של `raised_markers.dart`). **הקובע הוא מבנה התג, לא מספריות התוכן:**

| כתיבה | תיבה? | למה |
|---|---|---|
| `<sub>` — כל sub שהוא | **לא** | מומר לספרות-תחתיות יוניקוד או ל-`<span class="subscript-text">`; האטריביוטים נזרקים |
| `<sup class="footnote-marker">` | **לא** | נפלט כ-`<span class="footnote-marker-number">` |
| `<sup>` חשוף — `<sup>5</sup>`, `<sup>(א)</sup>` | **לא** | נפלט כ-`<span class="raised-sup">` טקסט טהור, **שסדרו מובטח**. כמה סמנים חשופים בשורה בטוחים גם כשתוכנם אות עברית |
| `<sup style="…">`, `<sup><b>…</b></sup>` | **כן** | נשאר `<sup>`; fwfh מממש אותו ב-WidgetSpan, ומנוע Flutter משבץ placeholders בפסקת RTL בסדר ויזואלי |

השורה האחרונה היא המלכודת שקל לפספס: `<sup style="color: gray;">N</sup>` — סמן
ההערות של מנגנון הקובץ הנפרד (§4) — **הוא תיבה גם כשתוכנו מספר**, ולכן שני סמנים
כאלה בשורה אחת יוצגו הפוך. בסריקת הקורפוס (ספטמבר 2026) נמצאו 1,192 שורות כאלה
ב-20 קבצים נארזים. `<sup>N</sup>` בלי אטריביוט — בטוח.

ההרמה הוויזואלית של שני ה-span-ים נעשית בציור ב-`RaisedMarkerOverlay`, ולכן
שלושת מסלולי הרינדור עוברים דרך `processText` — כולל מצב הקריאה הרציף
(`continuous_reading_paragraph.dart`).

### מצב קריאה רציף (תנ"ך ותלמוד)

שורות מתמזגות לפסקה, ומנוע פשוט יותר מרנדר (`continuous_reading_paragraph.dart` —
