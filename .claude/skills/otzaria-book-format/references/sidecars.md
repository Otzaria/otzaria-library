# קבצי הלוואי: קישורים, מבנה חלופי, כותרות PDF

שלושה סוגי קבצים יושבים לצד תיקיית `ספרים` ומוסיפים לספר יכולות שאין בקובץ הטקסט.
כולם UTF-8, `indent=2`, `ensure_ascii=False`, ושם הקובץ נגזר מ**שם הספר** (בלי סיומת).

| קובץ | תיקייה | מה נותן | טבלאות ב-DB |
|---|---|---|---|
| `<ספר>_links.json` | `links/` | קישורים לספרים אחרים (מפרש/מקור/הפניה), עוגני-מילה, טווחים | `link`, `link_anchor`, `link_range`, `link_coverage` |
| `<ספר>_alt_toc.json` | `alt_toc/` | מבנה כותרות חלופי (פרשות/עליות) לצד ה-TOC הרגיל | `alt_toc_structure`, `alt_toc_entry`, `line_alt_toc` |
| `<ספר>_headings.json` | `links/` | מיפוי כותרת → מספר שורה, לסנכרון עם PDF מקביל | `tocEntry` (נקרא ע"י `PdfHeadings`) |

**הערה:** יצירת קישורי מפרש עצמה היא עבודתו של `otzaria-commentary-linker`, והכתיבה
ל-DB חי היא של `otzaria-db-linker`. כאן מוגדר **הפורמט** שהם מייצרים.

## 1. `_links.json` — קישור רגיל

מערך רשומות. שם הקובץ = **ספר המקור**; `path_2` = ספר היעד.

```json
[
  {
    "line_index_1": 39,
    "line_index_2": 1,
    "heRef_2": "רש\"י",
    "path_2": "רש\"י על צלח על פסחים.txt",
    "Conection Type": "commentary"
  }
]
```

| שדה | כלל |
|---|---|
| `line_index_1` | שורה בספר המקור, **1-based** (הגנרטור ממיר ל-0-based; אל תמירו בעצמכם). |
| `line_index_2` | שורה בספר היעד, 1-based. |
| `path_2` | `"<כותרת היעד>.txt"` — **חייב להיות שם הספר במאגר תו-בתו**, גרשיים כלולים. אי-התאמה = הרשומה נזרקת בשקט. |
| `heRef_2` | כתובת עברית לתצוגה. לא מזהה יציב. |
| `ref_2` | ציטוט ספריא קנוני באנגלית — **חובה** כשהיעד ספר ספריא. |
| `ref_1` | כנ"ל כשספר המקור הוא ספריא. `ref_1` ו-`ref_2` לא יופיעו יחד. |
| `"Conection Type"` | **עם n אחת.** `"Connection Type"` = הערך נקרא ריק. |

כללים נוספים:

- **שני צדדים של ספריא — אסור.** ספריא כבר מספקת את הקישור; הגנרטור מדלג פר-קישור.
- **שורת כותרת (`<h…>`) בכל אחד מהצדדים → הקישור מדולג.**
- **סדר פיזי חשוב:** כמה שורות מקור שמצביעות לאותה שורת יעד חייבות להופיע **ברצף**
  בקובץ — `groupConsecutiveLinks()` באפליקציה מקבץ לפי רצף. פיזור = קבוצות נפרדות בתצוגה.
- מזהה הקישור ב-DB יציב לפי `(sourceLineId, targetLineId, connectionTypeId)` — ריצה
  חוזרת מקבלת אותו id (חשוב ל-delta). אותו זוג שורות עם סוג אחר = שני קישורים.

### סוגי קשר

**מפרשים** (מוצגים בפאנל המפרשים, `LinkTypes.dependentTextTypes`):
`commentary`, `super_commentary`, `targum`, `midrash`, `parshanut`, `dibur_hamatchil`,
`elucidation`, `explication`.

**הפניות** (פאנל הקישורים): `reference`, `quotation`, `mesorat hashas`, `ein mishpat`,
`mishnah in talmud`, `related`, `allusion`, `liturgy`, `law`, `summary`, `sifrei mitsvot`,
`essay`, `linker`, `other`.

- ערך לא מוכר או ריק → `OTHER` (במסלול אוצריא, בלי הסקה).
- `source` **וירטואלי** — לעולם לא נשמר. הכיוון ההפוך נגזר בקריאה מהיפוך קישור
  `commentary`. רוצים "X יהיה מקור של Y"? החליפו מי המקור ומי היעד.
- `linker` נכתב רק ע"י פייפליין ה-linker האוטומטי — לא כותבים אותו ביד, אבל **לא
  נוגעים** ברשומות קיימות שלו.
- להצגה כמפרש חייבים בדיוק אחד משמונת ערכי המפרשים. `allusion`/`essay`/`law` יופיעו
  בפאנל הקישורים, לא כמפרש.

### `ref_2` — הכלל שמפיל את הפייפליין השבועי

ספרי ספריא מיובאים מחדש בכל שבוע ומספרי השורות בהם **זזים**. לכן:

- יעד ספריא (תלמוד, רש"י, תוספות, רשב"ם, תנ"ך, משנה תורה…) → **חובה `ref_2`**.
  בלעדיו: `new_target_ref_required`, והריצה נעצרת לפני בניית ה-DB.
- מקור ספריא → `ref_1` (`new_source_ref_required`).
- `ref_2` על יעד שאינו ספריא → `ref_2 side classification changed`.
- הזיהוי הוא **התאמת מחרוזת מדויקת** של שם היעד מול `.github/data/sefaria_he_titles.txt`.
  אין נרמול גרשיים. `רשי על שבת.txt` ≠ `רש"י על שבת.txt` — הראשון נופל בשקט
  ל-`irrelevant` ולעולם לא מתעדכן. כך נוצרו 739 רשומות מתות.
- הפורמט: ציטוט אנגלי קנוני — `"Shabbat 2a:2"`, `"Rashi on Shabbat 6a:13:1"`,
  `"Mishneh Torah, Foreign Worship and Customs of the Nations 4:7"`.
  לתלמוד: `.` = עמוד א = `a`, `:` = עמוד ב = `b` (`יבמות ג:, ה` → `Yevamot 3b:5`).
- `line_index_2` הוא **מטמון מתכלה** של ה-`ref` — כלי הסנכרון השבועי דורס אותו.

שער PR: `.github/workflows/validate-manual-links-refs.yml`. רענון רשימת הכותרות:
`.github/scripts/refresh_sefaria_he_titles.py <export-root>`.

## 2. `_links.json` — עוגן מילה

קישור רגיל + עיגון למיקום תו בתוך **שורת המקור** (כמו סמני האותיות בשער הציון):

```json
{
  "line_index_1": 2, "line_index_2": 2,
  "heRef_2": "שער הציון, סימן א, סעיף א אות ג",
  "path_2": "שער הציון.txt",
  "Conection Type": "linker",
  "start": 6, "end": 12
}
```

- `start`/`end` = אופסטי תו **גולמיים** (כולל תגי HTML) בשורת המקור. הגנרטור ממיר
  לאופסטי תו גלויים.
- בלי `end` → עוגן-נקודה (סמן בודד).
- ה-**תווית** נשלפת מ-`heRef_2`: מה שאחרי `" אות "` (`"…אות ג"` → `label="ג"`).
- **צד-מקור בלבד** (`side=0`). רוצים סמן בספר A שמצביע ל-B — A הוא `line_index_1`.
- העוגן נכתב רק אם קיים `link` בין אותן שתי שורות. אי אפשר "להמציא" קשר דרך עוגן.
- הדרך המומלצת: פייפליין ה-`linker/`, לא כתיבה ידנית.

## 3. `_links.json` — קישור טווח

שני שדות אופציונליים, 1-based וכוללניים:

```json
{ "line_index_1": 39,
  "line_index_2": 12, "line_index_2_end": 15,
  "heRef_2": "…", "path_2": "…", "Conection Type": "commentary" }
```

- הקישור נשאר מעוגן ב**שורת ההתחלה**; `link_range` שומר את הסוף; `link_coverage`
  את השורות שביניהן (שורות כותרת מדולגות אוטומטית — אין צורך לפצל סביבן).
- כל צד עצמאי. `end == start` = קישור רגיל.
- קצה הפוך / מעבר לסוף הספר / שורת כותרת → אזהרה, הטווח מושמט, הקישור נשמר.
- הייבוא אוטוריטטיבי: הסרת `line_index_X_end` בריצה חוזרת מוחקת את הטווח.

## 4. `_alt_toc.json` — מבנה כותרות חלופי (פרשות/עליות)

**זה אינו קישור** אלא תוכן עניינים מקביל, שאינו נוגע ב-TOC הרגיל שנבנה מתגי `<h>`.

```json
[
  { "key": "Parasha", "heTitle": "פרשה",
    "nodes": [
      { "heTitle": "בראשית", "line": 1, "children": [
          { "heTitle": "עליה א", "line": 1 },
          { "heTitle": "עליה ב", "line": 36 } ] },
      { "heTitle": "נח", "line": 154, "children": [] }
    ] }
]
```

- מערך של מבנים. `key` — מזהה יציב באנגלית, **אל תשנו אותו** (בסיס ה-id ל-delta).
- כל node: `heTitle` (חובה), `line` (חובה, 1-based), `children` אופציונלי ורקורסיבי.
- `line` מותר שיהיה שורת כותרת או שורת תוכן; פרשה ועלייה ראשונה יכולות לחלוק שורה
  (העמוקה מנצחת במיפוי).
- ולידציה: `line` מחוץ לטווח או שורה כפולה תחת אותו הורה → הצומת מושמט (וילדיו איתו).
- **הקובץ אוטוריטטיבי:** הסרת `key` מוחקת את המבנה; מחיקת הקובץ מוחקת את כל מבני הספר.
- קובץ שמכוון לספר ספריא — מדולג באזהרה.

## 5. `_headings.json` — כותרות ל-PDF מקביל

מילון פשוט `{"כותרת": מספר שורה}`, בסדר עולה, יושב ב-`links/`:

```json
{ "בבא בתרא": 1, "דף ב.": 2, "דף ב:": 9, "דף ג.": 27 }
```

- ממפה כותרת בספר ה-PDF לשורה בקובץ הטקסט המקביל — כך הצגת PDF ופאנל המפרשים
  מסתנכרנים. באפליקציה זה נטען היום מטבלת `tocEntry` (`lib/models/pdf_headings.dart`).
- הכלים שסורקים `links/` מתעלמים מקבצים אלה לפי הסיומת `_headings.json` — אל תשנו
  את המוסכמה.

## 6. בדיקה

```bash
python -X utf8 scripts/validate_sidecars.py \
  --links "<repo>/MoreBooks/links/ספר_links.json" \
  --book  "<repo>/MoreBooks/ספרים/אוצריא/…/ספר.txt" \
  --books-root "<repo>" \
  --sefaria-titles "<repo>/.github/data/sefaria_he_titles.txt"

python -X utf8 scripts/validate_sidecars.py --alt-toc "…/alt_toc/ספר_alt_toc.json" --book "…/ספר.txt"
python -X utf8 scripts/validate_sidecars.py --headings "…/links/ספר_headings.json" --book "…/ספר.txt"
```
